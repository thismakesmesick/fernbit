HTML Textbook

This page is my running explanation of every HTML term I currently use in this site. I treat it like a reference page for myself, and I should update it whenever I add a new tag or attribute anywhere in the code.

Elements I Use

<!DOCTYPE html>

I use the doctype at the very top of the file to tell the browser to use modern HTML rules. Without it, browsers can fall into older compatibility behavior that makes layouts and styling weird.

<html>

I use the <html> element as the outer wrapper for the entire page. Everything on the page lives inside it.

<head>

I use <head> for metadata and setup information. This is where I put page settings, the title, stylesheet links, and external scripts that prepare the page.

<meta>

I use <meta> to give the browser extra information about the page, like character encoding and mobile viewport behavior. It does not display visible content by itself.

<title>

I use <title> to control the text shown in the browser tab and bookmarks. Each page gets its own title so I can tell tabs apart.

<link>

I use <link> to connect external resources to the page. In this site I mainly use it to load the shared stylesheet.

<body>

I use <body> for all visible content. If a visitor can actually see or interact with it, it belongs somewhere inside the body.

<header>

I use <header> for the top introductory area of a page or section. On my home page it holds the site title and short tagline.

<nav>

I use <nav> for the group of links that help people move around the site. This tells browsers and screen readers that the links are navigation, not random text links.

<ul>

I use <ul>, which means unordered list, when I have a list where order does not matter. My navigation menu is a good example because the items are choices, not steps.

<li>

I use <li> for each single item inside a list. It always lives inside a list container such as <ul>.

<a>

I use <a>, which means anchor, to create links. The link becomes clickable and sends the visitor to the location defined by its href.

<main>

I use <main> for the primary content of a page. There should only be one main landmark per page because it is supposed to represent the central content, not everything.

<section>

I use <section> to group related content into meaningful chunks. It helps me organize the page into topics instead of making one huge pile of elements.

<h1>

I use <h1> for the top-level heading of a page. It is the strongest heading and usually names what the page is mainly about.

<h2>

I use <h2> for the next heading level under the main page heading. I use it for major page sections and glossary entries.

<p>

I use <p> for ordinary paragraph text. It is the default choice when I just need a block of readable writing.

<footer>

I use <footer> for closing page information, such as copyright text or other end-of-page details.

<script>

I use <script> to load or write JavaScript. In this site I use it both to import outside libraries and to run my own page behavior.

<div>

I use <div> as a generic container when I need to group things together but there is not a more meaningful semantic tag for the job.

<article>

I use <article> for a self-contained piece of content. My blog entries fit that idea because each post can stand on its own.

<button>

I use <button> for interactive controls that do something on the page. In the blog, the post header is a button because clicking it opens and closes content.

<span>

I use <span> for small inline pieces of text that need styling or structure without becoming their own block. In the blog headers I use spans for the date and title.

Attributes I Use

lang

I use the lang attribute on <html> to say what language the page is written in. This helps screen readers, browsers, and search engines understand the content better.

charset

I use charset on a meta tag to set the character encoding. I use UTF-8 so letters, punctuation, and symbols display correctly.

name

I use name on metadata when I need to identify what kind of meta information I am setting. The viewport meta tag uses it to say what the setting is for.

content

I use content to hold the actual value of a meta tag. For example, it contains the viewport settings that tell mobile browsers how to scale the page.

rel

I use rel on a link tag to describe the relationship between my page and the file I am linking to. In this site it says the linked file is a stylesheet.

href

I use href to tell a link where it should go. If I change the value, I change the destination.

id

I use id when one element needs a unique name. This is useful for CSS targeting, JavaScript lookups, and anchor links.

class

I use class when multiple elements need to share the same styling or behavior. Unlike an id, a class is meant to be reused.

title

I use the title attribute for extra descriptive text on an element. On the CMS shortcut link, it gives a small label explaining what the control does.

aria-label

I use aria-label to give accessible text to an element when the visible content alone might not explain it clearly enough. This helps screen reader users understand controls.

src

I use src on a script tag to point to the JavaScript file I want to load. It is the address the browser fetches.

defer

I use defer on an external script when I want the browser to download it during page load but wait to run it until the HTML structure is ready.

type

I use type on buttons to be explicit about what kind of button they are. I set it to button so it acts like a normal clickable control instead of a form submit button.

aria-expanded

I use aria-expanded on the blog accordion buttons to describe whether each post is currently open or closed. This makes the interaction more understandable for assistive technology.

hidden

I use the hidden attribute to mark content that should not be shown yet. In my blog, the post body starts hidden until the matching button is clicked.
